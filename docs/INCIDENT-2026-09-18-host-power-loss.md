# เครื่องโหนดดับกลางคันสองครั้งระหว่างรันงานวัดผล (2026-09-18)

> เครื่อง `DESKTOP-2797V5R` · GTX 1070 Ti 8 GB · driver 581.57 · Windows 11 Pro 26200
> บันทึกไว้เพราะเจ้าของเครื่องสังเกตเห็นเองว่า "รีไปหลายรอบแล้ว" และสั่งให้ไล่หาสาเหตุ

## เกิดอะไรขึ้น

เครื่องดับทันทีโดยไม่มีสัญญาณเตือนสองครั้งในคืนเดียว แล้วบูตกลับมาเอง

| ดับเมื่อ | บูตกลับ | ห่างกัน |
|---|---|---|
| 22:02:11 | 22:03:21 | 70 วินาที |
| 22:33:27 | 22:34:11 | 44 วินาที |

ก่อนหน้านี้ Event 41 ครั้งล่าสุดคือ **12 ก.ย.** — ห่างกันหนึ่งสัปดาห์ สองครั้งนี้จึงไม่ใช่เรื่องที่เกิดประจำ

## ไม่ใช่ซอฟต์แวร์แครช

ลายเซ็นของทั้งสองครั้งเหมือนกันทุกช่อง:

```
Microsoft-Windows-Kernel-Power  Event 41
  BugcheckCode         = 0     ← ไม่มีจอฟ้า ไม่มี crash dump
  PowerButtonTimestamp = 0     ← ไม่ได้กดปุ่มปิด ไม่ได้กดค้าง
  SleepInProgress      = 0     ← ไม่ใช่การเข้า/ออก sleep
  HardwareError        = ว่าง
```

และไม่มีอย่างอื่นเลยในช่วงเดียวกัน:

- **ไม่มี Event 1001 (BugCheck)** → ไม่ใช่ BSOD
- **ไม่มี Event 4101** → ไดรเวอร์จอไม่ได้รีเซ็ต (ไม่ใช่ TDR)
- **ไม่มี WHEA-Logger** → ฮาร์ดแวร์ไม่ได้รายงาน error ให้ระบบรู้

ทั้งหมดนี้แปลว่า **ซีพียูหยุดทำงานกลางอากาศ ไฟหายไปดื้อ ๆ** ระบบไม่ทันได้เขียนอะไรลงดิสก์เลย
ถ้าเป็นไดรเวอร์แครชจะมี 4101 ถ้าเป็นความร้อนจะ throttle ก่อน ถ้าเป็น bug ในเคอร์เนลจะมี dump

## สาเหตุ

**งานที่ผมสั่งรันเอง** ไฟล์ log ของ ComfyUI หยุดเขียนตรงกับวินาทีที่เครื่องดับทั้งสองครั้ง:

| ไฟล์ | เขียนครั้งสุดท้าย | เครื่องดับ |
|---|---|---|
| `comfy-normal.log` | 22:02:45 | 22:02:11 |
| `comfy2.log` | 22:33:36 | 22:33:27 |

ท้ายไฟล์ `comfy2.log` คือ SDXL กำลังเดิน KSampler:

```
0%|  | 0/14 ... 100%|██████████| 14/14 [00:47<00:00, 3.41s/it]
Requested to load AutoencoderKL
```

งานนี้คือการวัดว่า SDXL บนการ์ด 8 GB เร็วแค่ไหน **เมื่อไม่ใช้ `--lowvram`** ซึ่งเป็นแฟล็กที่
ผมถอดออกเองเพื่อทดลอง ผลคือโมเดลอยู่ใน VRAM เต็ม ๆ และ GPU ทำงาน 100% ต่อเนื่องหลายสิบวินาที
ต่างจากตอนมี `--lowvram` ที่ช้ากว่าและกินไฟเป็นช่วง ๆ เพราะสลับน้ำหนักผ่าน PCIe ตลอดเวลา

## เรื่องที่เจอระหว่างทาง และสำคัญกว่าตัวเหตุการณ์

```
Current Power Limit : 90.00 W     ← ค่าที่ใช้อยู่จริง
Default Power Limit : 180.00 W    ← สเปคโรงงานของ GTX 1070 Ti
Min Power Limit     : 90.00 W     ← ต่ำสุดที่การ์ดยอมให้ตั้ง
Max Power Limit     : 217.00 W
```

**การ์ดถูกจำกัดไฟไว้ที่ค่าต่ำสุดเท่าที่ตั้งได้ = ครึ่งหนึ่งของสเปค** ไม่มีใครตั้งค่านี้โดยบังเอิญ
มันคือค่าที่คนตั้งเมื่อเครื่องเคยมีปัญหาเรื่องไฟมาก่อน และถึงจะจำกัดไว้แล้วก็ยังดับได้ภายใต้
โหลดต่อเนื่อง — เพราะเพดานไฟคุมค่าเฉลี่ย ไม่ได้คุมพีคชั่วขณะที่กินจากคอยล์ PSU

ข้อสันนิษฐานที่ตรงกับหลักฐานที่สุด: **PSU จ่ายไม่ทันตอนโหลดพุ่ง หรือวงจรป้องกันตัด**
(ไม่ใช่ข้อสรุป — ต้องวัดของจริงถึงจะฟันธงได้ ดูหัวข้อถัดไป)

## ผลกระทบต่อสิ่งที่วัดไว้ก่อนหน้า — ต้องแก้ตัวเลขในบันทึก

ตัวเลขทั้งหมดที่ใช้คาลิเบรตระบบประเมินเครื่อง **วัดบนการ์ดที่ถูกจำกัดไฟไว้ครึ่งเดียว**
เครื่องนี้จึงไม่ใช่ตัวแทนของ GTX 1070 Ti ทั่วไป — การ์ดปกติจะได้คะแนนสูงกว่านี้พอสมควร

| ตัวเลขที่บันทึกไว้ | สถานะ |
|---|---|
| งานอ้างอิง 3.07 วิ → score ~400-500 tier silver | วัดที่ 90W ไม่ใช่ 180W |
| SDXL 768² = 279 วิ (`--lowvram`) | วัดที่ 90W ด้วย |
| Wan 2.1 1.3B = 185 วิ | วัดที่ 90W ด้วย |
| `ReferenceBaselineSeconds = 1.5` (อ้างว่า ≈ RTX 3060) | ฐานที่ใช้เทียบยังใช้ได้ แต่ตำแหน่งของเครื่องนี้บนสเกลเลื่อน |

**ยังไม่ต้องรีบแก้ค่าคงที่ในโค้ด** — สเกลยังถูกต้องในตัวมันเอง สิ่งที่ผิดคือการเอาเครื่องนี้
ไปอ้างว่า "1070 Ti ทำได้เท่านี้" ซึ่งต้องเขียนกำกับไว้ทุกครั้งที่อ้างตัวเลขพวกนี้

## สิ่งที่ต้องทำต่อ

### ทันที
- [x] หยุดงาน GPU ทั้งหมด ไม่รัน benchmark ซ้ำจนกว่าจะรู้สาเหตุแน่
- [ ] ถ้าจะเปิด ComfyUI อีก **ใส่ `--lowvram` กลับไป** ตามที่เครื่องนี้ตั้งไว้แต่เดิม

### เพื่อฟันธงสาเหตุ (เจ้าของเครื่องทำ)
- ยี่ห้อ/วัตต์ของ PSU และอายุการใช้งาน — 1070 Ti ขอ PSU 500W+ ที่ยังแข็งแรง
- ลองเสียบสาย PCIe แยกเส้น (ไม่ใช้สาย daisy-chain เส้นเดียวสองหัว)
- ถ้ามีเครื่องวัด ดู 12V rail ตอนโหลดเต็ม — ตกต่ำกว่า 11.4V คือ PSU ไม่ไหว
- ลองรันโหลดยาว ๆ โดยถอดการ์ดออก (ใช้ iGPU) ถ้าไม่ดับ = ชี้ไปที่การจ่ายไฟให้การ์ด

### เรื่องที่กระทบตัวผลิตภัณฑ์ — ไม่ใช่แค่เครื่องนี้
1. **โหนดที่ PSU ไม่ไหวจะดับกลางงานลูกค้า** งานหาย เครื่องหลุดจาก pool และเจ้าของไม่ได้เงิน
   โดยไม่มีใครรู้ว่าทำไม
2. **ไฟดับกะทันหันทำ SQLite พังได้** ซึ่งเจอมาแล้ววันนี้ (`database disk image is malformed`)
   — ตอนนั้นสาเหตุคือบั๊กการย้ายไฟล์ `-shm` ของเรา แต่ไฟดับก็ทำให้พังได้เหมือนกัน
   ตัว quarantine ที่เพิ่มไปใน v0.1.3 คุ้มครองทั้งสองกรณี
3. **ตัวประเมินเครื่องเองก็เป็นโหลดหนักต่อเนื่อง** — 2048² blur ×6 สองรอบ
   เครื่องที่ไฟไม่พอจะดับตั้งแต่ตอนประเมิน ก่อนได้รับงานจริงด้วยซ้ำ

### ที่ควรเพิ่มในไคลเอนต์
- อ่าน `Current Power Limit` เทียบ `Default Power Limit` ตอนประเมิน แล้วบันทึกไว้
  การ์ดที่ถูกจำกัดไฟคือการ์ดที่ให้กำลังไม่เท่าสเปค — คะแนนต้องมีหมายเหตุกำกับ
- ตรวจ Kernel-Power 41 ตอนเปิดโปรแกรม ถ้าเครื่องเพิ่งดับกะทันหันระหว่างที่โหนดกำลังทำงาน
  ให้บันทึกลง activity log และ**ลดโหลดลงเอง** แทนที่จะเดินหน้ารับงานต่อเหมือนไม่มีอะไรเกิดขึ้น

## วิธีดึงหลักฐานชุดนี้ซ้ำ

```powershell
# เหตุการณ์ปิด/เปิดเครื่อง
Get-WinEvent -FilterHashtable @{LogName='System'; Id=@(41,1074,6005,6006,6008,1001); StartTime=(Get-Date).AddDays(-7)}

# รายละเอียดว่าเป็นไฟดับหรือแครช
Get-WinEvent -FilterHashtable @{LogName='System'; Id=41} | ForEach-Object { ([xml]$_.ToXml()).Event.EventData.Data }

# เพดานไฟของการ์ด
nvidia-smi -q -d POWER
```
